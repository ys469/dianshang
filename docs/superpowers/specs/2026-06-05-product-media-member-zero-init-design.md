# 商品图片/简介与新会员零初始化设计

## 背景

当前系统已经支持管理员新增商品、调整库存，以及用户注册登录后读取会员中心数据，但还有两个现实缺口：

1. 管理后台新增商品时，不能录入商品图片和完整简介。
2. 新注册账号在第一次生成会员资料时，默认初始余额不是 0，不符合真实商城“新用户从零开始”的要求。

本次改动的目标是在不推翻现有链路的前提下，把这两处补成完整可用的业务能力。

## 目标

1. 管理员新增商品时，可以填写商品图片链接和商品简介。
2. 商品创建后，后台商品列表和对外商品接口都能返回图片和简介。
3. 新账号第一次生成会员资料时，余额、积分、优惠券、成长值、累计订单、累计消费全部从 0 开始。
4. 老账号再次登录或访问会员接口时，继续读取已有会员数据，不重置。

## 不做的内容

1. 本轮不做图片文件上传到服务器。
2. 本轮不接入云存储。
3. 本轮不重构商品详情页版式，只补齐数据结构与后台录入展示。

## 方案

### 1. 商品管理补充图片和简介

后台商品新增表单新增两个字段：

1. `image`：商品图片链接，使用 URL 文本输入。
2. `description`：商品简介，使用多行文本输入。

后端商品模型补充 `description` 字段，管理员创建商品时一并写入运行时商品数据。现有 `image` 字段继续沿用，但从“后端可接收、前端未暴露”改为“前后端完整录入与展示”。

管理后台商品列表中：

1. 每个商品显示缩略图。
2. 商品名称区域显示副标题和简介摘要。

### 2. 新会员零初始化，老会员保留历史数据

当前 `RuntimeDataService.ensureMemberProfile()` 在新建会员资料时会给默认初始余额，这会导致新账号第一次登录就带余额，不符合要求。

改为：

1. 新建会员资料时，默认：
   - `balance = 0`
   - `points = 0`
   - `coupons = 0`
   - `growthValue = 0`
   - `totalOrders = 0`
   - `totalSpent = 0`
   - `lastOrderAt = null`
2. 已存在会员资料时，按 `authUserId` 或 `mobile` 命中原记录，直接返回，不覆盖现有余额、积分、优惠券和消费累计。

这样能保证：

1. 新账号第一次注册/登录时看到的是真实空账户。
2. 充值、下单、后台调账后的老账号数据不会因为再次登录被重置。

## 代码范围

### 管理后台

- `apps/admin/src/views/products/ProductListView.vue`
  - 商品新增表单增加图片链接、商品简介
  - 商品列表增加缩略图和简介摘要

- `apps/admin/src/services/api.ts`
  - `AdminProduct` 增加 `image`、`description`
  - `CreateProductInput` 增加 `image`、`description`

### API

- `apps/api/src/modules/admin/admin.controller.ts`
  - 管理员新增商品接口接收 `description`

- `apps/api/src/modules/runtime-data/runtime-data.service.ts`
  - `ProductRecord` 增加 `description`
  - `CreateProductInput` 增加 `description`
  - `createProduct()` 保存图片和简介
  - `toProductView()` / `getProductDetail()` / `getAdminProducts()` 返回图片和简介
  - `ensureMemberProfile()` 将新会员初始值改为 0，同时保留老会员历史数据

## 数据流

### 商品新增

1. 管理员在后台填写名称、分类、价格、库存、标签、图片链接、商品简介。
2. 前端调用 `/admin/products`。
3. 后端写入运行时商品集合。
4. 返回完整商品对象。
5. 后台列表立即插入新商品，后续前台商品接口和营销活动继续引用同一商品记录。

### 新会员首次登录

1. 用户注册成功或首次登录。
2. 认证服务调用 `ensureMemberProfile()`。
3. 若不存在会员资料，则新建并全部从 0 初始化。
4. 若已存在，则返回原数据。

## 测试

新增或补充 API 侧回归测试：

1. 管理员创建商品时，图片链接和商品简介可以保存并在管理员商品列表中读回。
2. 新注册账号获取会员资料时，余额、积分、优惠券、成长值、累计订单、累计消费均为 0。
3. 老账号在已有余额或订单后再次登录，会员资料保持原值，不被重置。

## 风险与处理

1. 商品图片使用 URL 输入，管理员可能填错链接。
   - 处理：本轮允许空值或无效链接作为业务输入，前端仅做基础格式提示，不阻塞主流程。

2. 现有种子会员数据中有老账号带历史余额和订单。
   - 处理：只修改“新建会员资料”的默认值，不改已有种子数据。

## 验收标准

1. 管理后台新增商品时可以填写图片链接和商品简介。
2. 新增商品后，后台商品列表能看到图片和简介摘要。
3. 管理接口和公开商品接口都返回 `image` 和 `description`。
4. 新注册账号首次进入会员中心时，余额、积分、优惠券、成长值、累计订单、累计消费全部为 0。
5. 老账号再次登录后，原有会员数据保持不变。
